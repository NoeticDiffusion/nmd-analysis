# BENCH-002 GO/NO-GO — ds003838, 2026-10-09

## Decision

**No-go for a 65-participant, all-load full-v3.1 BENCH-002 run on ds003838 under
the frozen 20-second contract.** Only load 13 has 20-second trial support. The
pilot establishes a useful separate path: the existing four-second fast-core
estimators are computable at all three loads, but that is a distinct
four-coordinate benchmark, not a full-v3 comparison.

For a question that requires the full eight-coordinate collection across all
loads, prefer a dataset with condition blocks long enough for the frozen
20-second support (and longer uninterrupted trajectories for MNJ). A
load-13-only full-v3 comparison remains a possible narrower design, but answers
only a one-load question and still needs an explicit task-contrast analysis
plan.

## Evidence

### Trial support

The six-participant coverage audit found identical structural trial support on
native and Core19 surfaces:

| Duration | Load 5 | Load 9 | Load 13 |
|---:|---:|---:|---:|
| 4 s | 324/324 trials | 324/324 | 324/324 |
| 8 s | 324/324 | 324/324 | 324/324 |
| 12 s | 0/324 | 324/324 | 324/324 |
| 20 s | 0/324 | 0/324 | 324/324 |

For each candidate, all eligible first-window probes at 4, 8, and 12 seconds
returned a computed, valid, finite value: 1,944/1,944 candidate rows at 4
seconds, 1,944/1,944 at 8 seconds, and 1,296/1,296 at 12 seconds. The
hash-checked 20-second pilot rows also returned 648/648 candidate values. These
counts combine both surfaces; each surface has half the count. All 20-second
window keys and exact sample boundaries matched the audited trial grid.

The BENCH-002 pilot's outer loop was the implementation restriction: it
invoked the candidate pipeline only after a trial passed the full-v3
20-second-window check. Therefore fast-core at load 5 and 9 was not unsupported;
it was never invoked there. The audit independently ran PCV, TP, OI, and SC at
4 seconds for all three loads without changing their estimator definitions.

### Short-duration characterization

The paired load-13 characterization compares nested 4/8/12-second prefixes
with the same trial's 20-second value. The table shows six-participant medians
and ranges of participant-level Lin concordance at 12 seconds:

|---|---:|---:|
| PCV | 0.833 (0.693–0.892) | 0.816 (0.680–0.900) |
| TP | 0.923 (0.826–0.981) | 0.929 (0.870–0.984) |
| NIE | 0.933 (0.815–0.976) | 0.938 (0.807–0.973) |
| RD | 0.378 (0.181–0.679) | 0.296 (0.216–0.675) |
| OI | 0.935 (0.877–0.978) | 0.927 (0.862–0.959) |
| SC | 0.775 (0.357–0.932) | 0.777 (0.414–0.923) |
| ED | 0.890 (0.784–0.951) | 0.889 (0.815–0.968) |

This is mixed, candidate-specific evidence, not a pass/fail test. RD's
short-window realization differs substantially in level from the 20-second
value and retains low concordance at 12 seconds. SC varies across participants
and uses duration-specific randomized references. PCV's window-local filter
edge fidelity is unassessed. ED's 12-second covariance outputs are finite, but
temporal effective sample size and short-window covariance bias remain
unresolved. The 12-second results justify designing a separate candidate-level
validation study; they do not justify calling the eight-coordinate vector a
validated multi-resolution v3 realization.

AR's shorter vectors matched the corresponding prefixes of the 20-second
vectors exactly in every paired load-13 window: 648/648 components at 4
seconds, 1,944/1,944 at 8 seconds, and 3,240/3,240 at 12 seconds. This checks
the nested block calculation; each duration still returns only 1, 3, or 5 of
the full 9 components.

### Qualification and provenance

No row was scientifically qualified. `bad_interval_free` remains unknown
because the supplied BIDS events have recording boundary markers but no
bad-interval annotations. Upstream composite filter edge safety was not
separately quantified. The numerical outputs demonstrate computability only.

## Recommended next steps

1. Keep the 20-second full-v3 path load-13-only for this dataset. Do not launch
   the 65-participant run under an all-load claim.
2. If the question is an all-load fast-core contrast, design it as a separate
   four-second `[PCV, TP, OI, SC]` realization. Update the extraction runner so
   fast-core windows are evaluated independently of the full-v3 gate, and give
   these outputs an explicit duration/surface identity. Do not label this
   result full v3.1.
3. Treat 12-second values as candidate-level experimental realizations. Before
   any broader run, specify separate estimator IDs and validate their intended
   use on independent data. RD, SC, PCV, and ED need particular attention.
4. If the primary aim remains a full-v3 or MNJ comparison across conditions,
   screen a dataset with longer, repeated condition blocks and adequate
   uninterrupted temporal support.

No classifier, condition contrast, optimization, or full-cohort analysis was
run for this decision. The 65-participant run remains unlaunched.
